##### SWEBOK: Cuerpo de conocimientos de ingeniería de software

El SWEBOK es un estándar de conocimiento que describe las mejores prácticas y conceptos fundamentales para la Ingeniería de Software. Publicado por el IEEE, el SWEBOK organiza el conocimiento de la ingeniería de software en diversas áreas clave:

**M.Sc. Ing. Fabrizio Calienes Rodríguez**

##### 1. Proceso de software:

o Define las actividades y resultados esperados a lo largo del ciclo de vida del software. o Se centra en la planificación, gestión y optimización del proceso de desarrollo.

##### 2. Requisitos de software:

o Se refiere a la identificación, análisis, especificación y validación de los requisitos del sistema que se va a desarrollar.

##### 3. Diseño de software:

o Defina la arquitectura y las estructuras de software que guiarán su implementación. o Cubre el diseño a nivel alto (arquitectura) ya nivel bajo (detalles de los componentes).

##### 4. Construcción de Software:

o Incluye la codificación, pruebas de unidad y depuración del software.

##### 5. Pruebas de software:

o Abarca las actividades relacionadas con la verificación de que el software cumple con los requisitos definidos.

##### 6. Mantenimiento de software:

o Describe las actividades para corregir, mejorar o adaptar el software una vez que haya sido desplegado.

##### 7. Gestión de Proyectos de Software:

o Se centra en la planificación, monitoreo y control de proyectos de software, asegurando que se entreguen a tiempo y dentro del presupuesto.

##### Parte 1: Introducción al Proyecto y Planificación del Proceso de

##### Desarrollo

##### 1.1 Introducción a SWEBOK

- Presentación de las principales áreas del conocimiento de SWEBOK.
- Explicación del Proceso de Software y sus fases clave en el ciclo de vida del software.
##### 1.2. Presentación del Proyecto

Se le pedirá al grupo que desarrolle un sistema de reservas en línea para una cadena de restaurantes. El sistema debe permitir:

- Reservar mesas.
- Cancelar o modificar reservas.
- Enviar notificaciones de confirmación al cliente.
##### 1.3. Planificación del Proceso de Desarrollo

Cada grupo debe crear un plan de desarrollo de software que incluya:

- Fases del ciclo de vida según el SWEBOK.
- Definición de entregables por fase.
- Estimación de tiempo para cada actividad.
##### Parte 2: Requisitos y Diseño de Software

##### 2.1. Requisitos de software

- Los estudiantes deberán realizar una reunión con el "cliente" (profesor o compañero) para recolectar los requisitos del sistema.
- Elaborar un documento de especificación de requisitos que incluya: o Requisitos funcionales y no funcionales. o Restricciones del sistema.
##### 2.2. Diseño de software

- Los estudiantes deben diseñar la **arquitectura del sistema** utilizando diagramas UML. o Crear un diagrama de clases para la estructura del sistema. o Definir la interacción de los componentes clave con un diagrama de secuencia.

##### Parte 3: Construcción y Pruebas de Software

##### 3.1. Construcción del software

- Utilice un entorno de diseño para comenzar a diseñar los módulos clave del sistema (MOCKUPS).
- Implementar las funcionalidades básicas, como la gestión de reservas y notificaciones.
##### 3.2. Pruebas de software

- Realizar pruebas unitarias de los componentes desarrollados (DOCUMENTACION).
- Se debe redactar un plan de pruebas que incluya: o Casos de prueba para cada funcionalidad. o Resultados esperados y criterios de aceptación.
##### Parte 4: Mantenimiento y Revisión del Proyecto

##### 4.1. mantenimiento de software

- Simulación de un cambio en los requisitos: el cliente solicita una nueva funcionalidad (por ejemplo, un sistema de recompensas para clientes frecuentes).
- El grupo de trabajo debe: o Actualizar el documento de requisitos. o Implementar los cambios en el código y realizar pruebas de regresión.
##### 4.2. Revisión y Presentación del Proyecto

- Cada grupo debe presentar su trabajo final, incluyendo: o La planificación del proyecto. o El documento de requisitos y diseño. o El diseño de las interfaces. o Resultados de las pruebas.
